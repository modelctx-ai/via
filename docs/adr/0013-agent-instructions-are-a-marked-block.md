# 0013. agent 说明以标记块注入，而不是覆盖整份文件

- 状态：已接受
- 日期：2026-10-21

## 背景

`via prompt` 的作用是把一段说明放进 AGENTS.md 之类的文档里，让 agent 知道该用 `via` 而不是把工具 schema 全塞进上下文。0.3 之前的做法是 `--out <文件>` 整份写入：目标文件已存在就要求 `--yes`，否则退出码 5。

问题在于目标文件几乎总是**用户自己的**。AGENTS.md 往往写着项目约定、命令、注意事项；`--yes` 覆盖等于把它清空重写。于是用户实际只有两个选择：手动复制粘贴（下次升级 via 时又得记得改，很快就漂移），或者冒险覆盖。`via doctor` 报「框架还在注入 schema」时，用户被要求把说明放进仓库，却没有任何不丢内容的写法。

另有一个次要问题：说明以 `# External tools (via)` 开头。写进别人的文档后，这个 H1 会和文档自己的标题并列，破坏大纲。

## 决策

- `via prompt` 输出一段**带标记的块**：`<!-- via:begin … -->` 与 `<!-- via:end -->` 之间是说明本身与 provider 列表。标题降为 `##`。
- 标记用 HTML 注释，不用 `<tag>` 形式的 XML。AGENTS.md 是 Markdown，按 CommonMark，单独一行、不在块级白名单里的开标签会开启一个 HTML block 并延续到下一个空行，块内的 `#` 和 `-` 不再按 Markdown 解析，GitHub 上的渲染会降级。HTML 注释是行内 HTML，渲染时不可见，也不打断块内结构。
- `--out <文件>` 的语义改为拼接：
  - 文件不存在（或只有空白）→ 创建，内容就是这个块；
  - 已有唯一一对标记 → 只替换两个标记之间的内容，标记之外一个字节都不动；
  - 没有标记 → 追加到末尾，前面空一行；
  - 标记不成对、或出现多对 → 拒绝，退出码 5，提示手工修。
- 新增 `--check <文件>`：块与当前输出一致退出码 0，没有块或内容过期退出码 1（`next:` 指向 `--out`），标记不可用退出码 5。供 CI 使用。
- `--replace` 保留旧行为（整份文件只留这个块），目标文件已存在时仍需 `--yes`。这是逃生门，不是默认路径。
- 说明内容增加两句：via 是什么，以及需要外部服务时优先用 `via` 而不是已挂载的 MCP 工具。

## 备选方案

- **保持整份覆盖，靠备份兜底**：与其说是方案，不如说是把风险转嫁给用户；仓库里的 AGENTS.md 是版本控制中的文件，备份目录不在其中，用户很难发现被覆盖。
- **让用户手工粘贴**：不需要改代码，但升级 via 后说明会停在旧语法，`via trust` 这类安全提示的措辞变化就传不到用户手里。
- **写进独立文件（`VIA.md`）再由用户 include**：多一次手工接线，而多数框架的 include 语法各不相同；标记块在同一个文件里就能表达「这块是生成的」。
- **用 XML 标签 `<via_cli>` 作为分隔**：对模型友好，但在 Markdown 文档里会打断渲染（见上）；标记是给人和工具找位置用的，模型读的边界已经由标题表达。
- **标记里写入版本号**：能一眼看出是否过期，但每次发版都会改一行，diff 噪音大；过期检测交给 `--check`。

## 后果

- 重跑 `via prompt --out AGENTS.md` 变成安全的日常操作：升级 via 后刷新说明，用户自己的内容不动。不需要备份机制，因为爆炸半径只有标记之间那几行。
- 标记损坏时宁可报错也不猜位置：写坏了用户的文字无法恢复，而报错只是多一步手工操作。
- 说明从约 150 token 长到约 175 token，标记再加约 25 token。这是「让 agent 知道该优先用什么」的代价；provider 列表按目录顺序生成，不分域。
- 需要在规范里讲清标记语义（cli.md）、在指南里给出完整块与四种文件状态（agent-integration.md）；两份 README 的第 4 步改为 `--out` + `--check`。

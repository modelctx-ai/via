# 0007. 不对任何网关做专门适配

- 状态：已接受
- 日期：2026-10-20

## 背景

曾考虑在 via 中识别 Asterlane 等网关的元工具（如 `asl__search`、`asl__call`），把网关挂载为子目录树，让 `via ls`、`find`、`more` 透传给网关，从而实现一层发现。

## 决策

via 不对任何网关做专门适配。网关对 via 来说是普通的 HTTP MCP server：配好 bearer 凭证，它暴露的元工具按通用规则命名（如 `via aster asl:search`）、映射参数和渲染输出。

## 备选方案

- **网关挂载模式**：agent 只需一层发现，体验更好，但 via 与特定网关的协议耦合，网关演进时 via 也要跟着改。

## 后果

- agent 要做两层发现：先在 via 里找到网关的元工具，再通过网关的搜索找到上游工具。
- via 与任何网关零耦合，代码中不得出现针对特定 server 或网关的分支逻辑。
- 如果将来两层发现的成本被评测证明过高，可以设计一个**通用的**目录协议扩展，而不是针对某个网关的适配；那需要新的 ADR。

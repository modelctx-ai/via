# 0022. 日志：按 server 分文件，按大小轮转，写盘前脱敏，不挡调用

- 状态：已接受
- 日期：2026-10-22

## 背景

排查「某个 server 为什么连不上、为什么慢、为什么这次调用失败」时，现在能看到的东西很少：stdio 子进程的 stderr 只在出错时取末尾几行拼进错误信息（[auth.md](../spec/auth.md#调用时的行为)：子进程 stderr 不转发，可能回显凭证），其余丢弃；daemon 的 `via.sock.log` 只在 daemon 启动失败时被读来拼错误信息，超过 64 KB 在下次启动时清空；协议协商的结果、连接何时建立与断开、daemon 为什么退出，都没有留下记录。agent 经 shell 调用时更看不到：stderr 没人盯着。

要加日志，但有几条不能松的约束：

- **凭证不得进日志**（[security.md](../spec/security.md)）：stdio 子进程完全可能把收到的环境变量或请求打印出来。
- **热路径不变慢**：调用路径上不做同步写盘。
- **不增加冷启动**：浏览命令不加载日志模块；调用路径和 daemon 本来就加载 SDK，日志模块很小。
- **文件权限与缓存目录一致**（POSIX 0700/0600；Windows 靠用户目录的 ACL，[security.md](../spec/security.md#windows-上的文件权限)）。
- 进程内模式（没有 daemon）也要有 stdio 的 stderr 日志：这是最需要它的场合（一次性进程，出错后什么都不剩）。

## 决策

**位置与布局**：用户缓存目录下的 `logs/`（目录 0700，文件 0600，与游标、媒体、目录缓存同处）。`logs/daemon.log` 是 daemon 自己的；`logs/servers/<名字>.log` 是各 server 的，名字是配置里 `servers` 下的键（含不安全字符时换成安全字符并加 8 位摘要，两个不同的名字不会共用一个文件）。同一个 server 的各个会话（不同目录下的同名 stdio server）写同一个文件。轮转：单个文件超过 1 MiB 时 `x.log` → `x.log.1` → `x.log.2` → `x.log.3`，最旧的丢弃，一份日志最多约 4 MiB；daemon 启动时删除两周没有写过的日志（server 已不在配置里）。放缓存目录而不是状态目录，因为 via 只有这两类目录，日志和缓存一样可以随时删除、丢了不影响功能。

**内容**：每行 `<ISO 时间> <标签> <文本>`，标签是 `event`（via 写的事件）、`error`、`stderr`（子进程的 stderr，一行一条）。server 日志里是：子进程启动（只写程序名，不写参数）或 HTTP 连接（只写 scheme 与主机）、协议探测的策略与协商结果（版本、有无状态、pid）、连接关闭、重订 `list_changed`、每次调用一行（工具的原始名、结果 `ok`/`returned isError`/失败的退出码和首行原因、耗时）、对用户提问的类型与结果（[ADR 0018](0018-elicitation-in-a-terminal-declined-elsewhere.md)，不含问题与答案的文字）、连接失败的原因。daemon 日志里是：启动（pid、版本、socket 路径；Windows 的管道名由令牌派生，不写）、连接的建立与关闭、握手被拒绝的原因、非调用请求的失败、`shutdown`、收尾、空闲退出、socket 被替换、崩溃。**不记录**参数、调用结果、资源内容、问题与答案、凭证。

**脱敏**：写盘之前，用与输出相同的脱敏器。via 自己写的 `event`/`error` 行按「via 组合的文字」规则（8 个字符以上的凭证）；子进程的 stderr 是内容，任何长度的凭证都替换（[output.md](../spec/output.md#脱敏的范围)）。stderr 按行处理：一行写完整才脱敏、才写入，所以跨两个数据块的凭证不会漏；一行超过 4096 个字符时脱敏之后再截断；没有换行却累积到 16 KiB 的行，把末尾 4096 个字符也丢掉（凭证可能刚好从那里开始）并忽略这一行余下的部分。控制字符、转义序列、双向文本控制符写成可见的 `\xNN`/`\uNNNN`，所以一行日志永远只是一行，`via daemon logs` 打印也不会移动光标（读取时再转义一遍，文件只是文件）。

**不挡调用**：`append` 只把一行放进内存队列；一个异步写入器约 100 毫秒（或积累 32 KiB）后一次写入并在需要时轮转，每次写入都是对整行的单次 `O_APPEND`，daemon 与进程内的 CLI 可以同时往一个文件里写。不长期持有文件句柄（别的进程可能已经轮转了它），每次写之前看一眼大小。写不进去（只读的缓存目录、磁盘满）时放弃这份日志，不影响任何调用。进程内模式在 session 关闭时 `flush`；进程被杀会丢最后不到 100 毫秒的行。

**查看**：`via daemon logs [<provider>] [-n <行数>] [--follow] [--since <时长>]`。不带 provider 是 daemon 自己的日志。`-n` 默认 50；`--since` 取 `30s`、`10m`、`2h`、`1d` 或它们的组合；`--follow`（`-f`）每 250 毫秒看一次文件，跟随轮转，直到被中断。读文件，所以 daemon 没运行、`VIA_NO_DAEMON=1` 下也能用（后者只有 server 的日志）。`-o json` 输出 JSON Lines（`time`、`source`、`text`）。

**不做**：不提供关闭日志的开关，也不做可配置的大小和份数（固定值足够，先不增加配置面）；不记录 HTTP 的请求与响应；不转发 server 的 MCP `logging` 通知（daemon 不转发 server 的日志，[daemon.md](../spec/daemon.md#协议版本与无状态连接)）；不把日志送往别处。

## 备选方案

- **放状态目录（`XDG_STATE_HOME`）**：更符合 XDG，但 via 没有这个目录的概念，要为此新增路径、文档和 Windows 对应；日志本来就可以随时删。
- **同步写**：简单，但每个 stderr 行一次 `write(2)` 会出现在调用路径上（stdio 子进程的 stderr 事件在同一个事件循环里），并发调用时互相排队。
- **长期持有文件句柄、自己算大小**：少几次系统调用，但多进程同时写同一个文件时大小会算错，别的进程轮转之后还在写已被改名的文件。
- **在每个 `stderr` 数据块上直接脱敏**：凭证被切在两个块之间时漏掉。
- **把日志做成 daemon 的功能（通过 socket 取）**：进程内模式没有 daemon，而它恰恰最需要日志；daemon 没运行时也要能看崩溃前的记录。

## 后果

- 每次连接 stdio server 的 CLI 进程会多一个异步写入（几行），daemon 里常驻的开销是一个定时器和一个队列。
- 缓存目录多一个 `logs/`，上限由「server 数 × 约 4 MiB」决定；两周没写过的被清理。
- `via.sock.log` 保留：它是分离启动的 daemon 的 stderr（日志模块起来之前的错误、未捕获的异常栈），仍只在启动失败时读取。
- 日志是用户私有数据：与目录缓存同样对待，Windows 上不宣称 0600。
- 新增测试夹具 `CLI_FIXTURE_STDERR_ENV`（stdio 夹具把一个环境变量的值写到 stderr，测试凭证不进日志）。

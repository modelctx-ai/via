## 先读这个：夹具的可信度

[夹具说明](../../test/fixtures/README.md#来源与可信度)：只有 `github`、`notion`、`cloudflare` 的工具名取自实际连接的 server；`linear`、`playwright`、`exa`、`filesystem`、`slack`、`puppeteer`、`context7`、`tavily`、`sqlite`、`postgres` 依据公开的工具列表整理，不保证逐字一致；`gmail`、`google-drive` 是为覆盖某种形态虚构的样本。所以下面的比例**说明规则在这十五个样本上的表现**，不是对「真实 server 的叶子比例」的无偏估计；要得到后者，需要更多真实 `tools/list`（把它们放进夹具后重跑本脚本即可）。`acme-*` 与 `aster` 是虚构的边缘样本，不计入。

“拆成 资源:动作”是冲突处理之后的最终结果。列含义：

- 无动词：名字里没有动词表中的词（规则 3 找不到动作）
- 只有动词：找到动词但没有剩余的词可作资源（只有动作）
- 冲突：两个工具拆出相同的 `资源:动作`，都退回为叶子（规则 6）
- 让名：资源与一个原始名恰为该名字的叶子同名，资源让出名字（规则 7）

## 对动词表的建议

以下由人写，不是生成的；重新运行 `npm run split-stats` 会保留这一节。数字来自上面的表；「改动前」的基线是 v0.3.1 的动词表，复现：把该标签的 `data/verbs.json` 取出为 `verbs-0.3.1.json`，再运行 `npm run split-stats -- --baseline-verbs verbs-0.3.1.json --out bench/results/0.4-split --release 0.4-dev`。

### 读数

- 15 个 server、231 个工具，动词表改动前 60 个退回为叶子（26.0%），改动后 51 个（22.1%）。只看工具名取自实际 server 的三个（`github`、`notion`、`cloudflare`，共 123 个工具）：18 个（14.6%）降到 15 个（12.2%）。
- **叶子大多不是规则出了错**，按原因：
  - 「只有动词」8 个（`search`、`fetch`、`query`、`navigate`、`click`……）：provider 词去掉后只剩动作本身，叶子名就是正确的规范写法，没有可改的。
  - 「冲突」与「让名」在这 15 个夹具上一个都没有出现（规则 6、7 是为 Anysearch 这类实测碰撞写的，夹具里没有）。
  - 「无动词」43 个，是动词表和规则能动的部分，下面分类。
- 比例集中在少数 server：playwright 与 puppeteer（浏览器自动化）占 22 个，tavily、cloudflare、exa 各 4 个，notion 8 个；github（53/54）、linear（22/22）、slack、filesystem 等「资源—动作」风格的 server 基本都能拆开。拆分失败的 server 有共同形态：工具名是 `前缀_动作词`（`browser_*`、`puppeteer_*`、`tavily-*`），或是单个名词/缩写（`whoami`、`docs`、`execute`）。

| --- | --- | --- |

| 名词形态的动作 | `browser_snapshot`、`browser_take_screenshot`、`browser_console_messages`、`directory_tree`、`company_research_exa`、`deep_researcher_start`/`_check`、`crawling_exa`、`tavily-map` | 动词表无能为力 |

### 已应用的动词表改动

`data/verbs.json` 增加 7 个词，版本 1 → 2：`edit`、`modify`、`append`、`download`、`upload`、`install`、`close`。入选标准（三条都满足）：

1. **通用动作**，不是某个领域的交互动词（`hover`、`drag` 留在建议里），而且几乎不会作名词或形容词用（`post`、`type`、`check`、`request` 会，见下）。
2. **不改变任何已有的 `资源:动作`**：逐词用 `npm run split-diff` 在 `tools/` 和 `other/` 全部夹具上验证，每个词只让原来的叶子变成 `资源:动作`。
3. **新拆出的名字都合理**：资源里没有 `to`、`for` 这类连接词，没有产生新的冲突（规则 6）。

受影响的规范写法，共 9 个（全是叶子 → `资源:动作`，没有已有规范名变化）：

| server | 原始名 | 之前 | 现在 |
| --- | --- | --- | --- |
| filesystem | `edit_file` | `edit-file` | `file:edit` |
| gmail | `modify_message` | `modify-message` | `message:modify` |
| notion | `notion-download-attachment` | `download-attachment` | `attachment:download` |
| notion | `notion-download-skill` | `download-skill` | `skill:download` |
| notion | `notion-upload-skill` | `upload-skill` | `skill:upload` |
| playwright | `browser_close` | `browser-close` | `browser:close` |
| playwright | `browser_file_upload` | `browser-file-upload` | `browser-file:upload` |
| playwright | `browser_install` | `browser-install` | `browser:install` |
| sqlite | `append_insight` | `append-insight` | `insight:append` |

**`deny` 不受影响**：`deny` 规则除了当前规范写法、原始名、默认规范写法，还匹配每个工具的叶子写法（`provider/去掉 provider 词的原始名，用 - 连接`，与动词表无关，config.md「deny」）。所以按旧叶子名写的规则（如 `^filesystem/edit-file$`）在这 9 个工具变成 `资源:动作` 之后照常命中，原始名写法同样。这是随这次改动一起加的保证（CHANGELOG 里单独一条），以后动词表再增减动词也一样。

`find` 的检索质量不变（调参集 recall@1 66.3%、recall@5 96.9%、MRR 0.790；留出集 66.7%、86.7%、0.775，与改动前逐位相同）：评测集里指向这几个工具的期望名随规范写法更新，查询本身没动。用户若在配置里用了原来的叶子名，原始名永远有效，`rename` 里写的原始名也不受影响（naming.md「稳定性约定」）。

### 建议，未应用（需要更多真实数据，或需要改规则）

| 词或规则 | 会改变的名字（夹具内） | 为什么没应用 |
| --- | --- | --- |
| `hover`、`drag`、`resize`、`evaluate`、`fill`、`select`、`press` | `browser:hover`、`browser:drag`、`browser:resize`、`browser:evaluate`、`browser-form:fill`、`browser-option:select`；`acme-puppet` 的 `script:evaluate` | 都是无歧义的动词，但只出现在浏览器自动化 server 里，且 `browser_*` 家族另有一半（`type`、`snapshot`、`take_screenshot`、`wait_for`、`console_messages`）拆不开，补一半会让 `via playwright` 的视图既有 `browser` 资源又有一排 `browser-*` 叶子。等有 playwright 与 puppeteer 的真实 `tools/list`，再决定是补全这一族，还是接受叶子 |
| `type`、`post`、`share`、`request`、`check` | `browser:type`、`message:post`、`file:share`、`copilot-review:request`、`deep-researcher:check`、`mcp-next-step:check`、…… | 同时是常用名词。首词在动词表里就取首词，所以 `post_create`、`check_run_update`、`type_list`、`request_log_get` 这类「名词_动作」会被错拆成 `create:post`、`run-update:check`……。夹具里没有这样的名字，但不能证明真实 server 里没有；要补就得先有这类反例的样本，或让规则在首词和末词都是动词时优先取末词 |
| `set`、`stop`、`start`、`spawn`、`wait` | `comment-reaction:set`、`session:stop`、`session:spawn`、`session:wait`、`deep-researcher:start` | 无歧义，各自只在 1–2 个工具里出现（Notion 的会话管理、exa 的 deep researcher）。证据太少，等同类工具多了再补；`wait` 另受下一条影响 |
| 资源首词是连接词时丢弃（`to`、`for`、`of`、`with`、`in`、`on`、`by`、`from`） | `reply_to_thread` → `to-thread:reply`（应为 `thread:reply`）、`wait_for_selector` → `for-selector:wait`、`browser_wait_for` → `browser-for:wait` | 这是规则（naming.md 规则 4）的改动，不是数据的改动，会让 `reply`、`wait` 这类词能放心收入。已有的 `list_directory_with_sizes` → `directory-with-size:list` 说明中间的连接词是现有行为，不能一起改。需要先写 ADR |
| `convert` | `convert-page-to-skill` → `page-to-skill:convert` | 资源里夹着 `to`，名字不好看，同样等连接词规则 |
| 无动词的前缀家族 | `browser_*` 的 15 个、`puppeteer_*` 的 7 个 | 如果「共享前缀、其余词不是动词」时以前缀为资源、其余词为动作（`browser:press-key`、`browser:take-screenshot`），能把这两族整齐地收进一个资源。但这是新的拆分规则，而且很难不变成对某类 server 的特判（ADR 0007），需要更多 server 的样本验证 |

### 没有做的

- 截断预算（8 KB）没有动：它等 d1 的 agent 评测。
- 没有扩充夹具：本节的结论受限于 15 个样本中只有 3 个是实际 server 的工具名。最有价值的下一步是把更多真实的 `tools/list`（尤其是 Playwright MCP、Puppeteer、Slack、Gmail、Google Drive）放进 `test/fixtures/tools/`，重跑 `npm run split-stats`，再回头看上面的建议。
